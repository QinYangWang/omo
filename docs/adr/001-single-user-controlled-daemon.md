# ADR-001：单个用户自控 daemon、离线语义与唯一写者

- 状态：已确认
- 规划依据：§1、§4.2、§4.3、§5.5
- 日期：v2 规划确认时

## 决策

1. omo v2 有且只有一个用户控制的权威 daemon；桌面、Web、移动端都只是它的客户端，连接同一权威状态。
2. daemon 关机、休眠或不可达时，客户端进入 `offline`：显示名称与最近在线时间，停止操作入口，隐藏会话正文、文件与终端内容。不用缓存冒充可访问的会话。
3. 一个 Session 的全部 lane 与写入权始终属于同一个 Session Worker；无法确认旧写者停止时，不根据超时强行启动第二个写者。
4. 不建设常在线云副本、Hub/Runner 网络、自动接管、多主合并与离线会话阅读。

## 后果

- Electron 不再直接创建 `AgentSession`，只负责 daemon 启动/配对、窗口与原生桥接；本地与远程客户端共用同一领域契约（允许 loopback 优化，不允许第二套业务语义）。
- 重连后按原 command ID 对账，不换 ID 重发；离线不产生待自动补发的执行命令。
- 客户端可保留认证材料、连接配置与未发送草稿，但不获得离线浏览能力。
- 三平台服务生命周期（Windows 服务/Job Object、macOS LaunchAgent、Linux user service）需要分别验证。

## 退出/再评估条件

用户改变「单 daemon、不常在线」产品边界时另立 ADR，不在本决策下为 Hub/接管/离线阅读付出实现成本。
